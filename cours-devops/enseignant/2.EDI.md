# Guide enseignant · Chapitre 2 · Introduction aux EDI et à Visual Studio Code
[← Support étudiant](../2.EDI.md)

## En bref

- **Durée :** 2h, une seule séance.
- **Matériel :** chaque étudiant a son ordinateur portable (droits d'installation nécessaires), Wi-Fi fonctionnel, vidéoprojecteur. Le poste du professeur a VS Code installé **en français**, sans personnalisation exotique (thème lisible au projecteur, police agrandie à 18 ou 20 via `Ctrl + ,` > *Font Size*, zoom `Ctrl + =`).
- **Prêt avant la séance :**
  - avoir demandé, à la fin du chapitre 1, d'installer VS Code chez soi (partie 2.4 du support) ;
  - avoir sur le poste du professeur l'installeur VS Code pour Windows et macOS sur une clé USB (si le Wi-Fi sature quand 30 personnes téléchargent en même temps) ;
  - ne pas avoir encore de dossier `~/cours-devops` sur le poste de démonstration (ou le renommer), pour faire la création en direct ;
  - un modèle `presentation.md` déjà rempli (votre propre fiche) pour le montrer en exemple.
- **Fil DataCafé :** Léa installe la nouvelle recrue sur son poste de travail : un éditeur, un terminal et une première fiche de présentation.
- **Les 3 messages clés :**
  1. Un EDI, c'est la **cuisine équipée** du développeur ; VS Code est l'outil standard, gratuit et extensible.
  2. Le **terminal** n'est pas réservé aux experts : 6 commandes suffisent pour se repérer et créer ses dossiers (indispensable pour Git au chapitre 3).
  3. Le **Markdown** est le format d'écriture de tout l'écosystème GitHub : la fiche `presentation.md` sera réutilisée au chapitre 4.

### Points d'animation

**💬 Tour de table et contrôle de l'installation (plan B)**

- Faire lever la main : « VS Code installé **et** il s'ouvre ? ». Compter. Puis « Qui a eu un problème ? ».
- **Plan B pour ceux qui ne l'ont pas installé :**
  1. Les placer à côté d'un voisin qui a VS Code : ils suivent le cours sur l'écran du voisin pendant que l'installation tourne.
  2. Ils lancent l'installation **pendant les 15 premières minutes** (cours EDI), qui ne demandent pas de manipulation. Si le Wi-Fi sature, faire circuler la clé USB.
  3. Objectif : tout le monde a VS Code ouvert à 0:35, au début de la démo. Les derniers bloqués (droits administrateur sur un ordinateur d'entreprise, disque plein) travaillent en binôme sur le poste du voisin pour toute la séance et retentent chez eux ; sur Windows sans droits admin, l'installeur **User** (`VSCodeUserSetup`) ne demande normalement pas de droits administrateur.
  4. Dernier recours : [vscode.dev](https://vscode.dev) dans le navigateur permet de suivre la partie Markdown (pas de terminal).
- Les questions 1 et 2 amènent l'idée de l'EDI : laisser 2 ou 3 réponses, puis enchaîner sur l'analogie de la cuisine.

**🎤 EDI et popularité**

- Demander à la classe : « Dans une cuisine équipée, qu'est-ce qui correspond au débogueur ? » avant de dévoiler le tableau.
- Insister sur le piège **Visual Studio ≠ Visual Studio Code** : certains étudiants installent le mauvais logiciel. Vérifier à la volée l'icône (bleue pour VS Code, violette pour Visual Studio).
- Si le temps manque : passer vite sur la liste des « options » et sur le tableau « quel EDI pour quel usage » (lecture autonome).

**🛠️ L'enquête PYPL** : exercice court, à couper en premier en cas de retard (le professeur affiche lui-même le site et commente).

**👀 / 🛠️ VS Code et extensions**

- Pendant l'exercice, les rapides peuvent faire les 🟡 et 🔴, puis aider un voisin.
- Pour les débutants : se concentrer sur les 3 extensions minimum (French Language Pack, Live Server, Markdown All in One). Les autres peuvent être installées à la maison.
- Le French Language Pack demande un redémarrage : prévenir avant, sinon des étudiants pensent que « ça n'a pas marché ».

**🎤 / 👀 / 🛠️ Terminal**

- C'est le moment le plus anxiogène pour les non-informaticiens. Dédramatiser : « Vous ne pouvez rien casser avec `pwd`, `ls` et `cd`. »
- Faire répéter à voix haute « où suis-je ? » (`pwd`) avant chaque nouvelle commande.
- Les étudiants sous Windows sont dans PowerShell : `pwd`, `ls`, `cd`, `mkdir` y fonctionnent (ce sont des alias). L'affichage de `ls` est différent (colonnes Mode, LastWriteTime...) : le signaler pour éviter l'inquiétude.
- Le dossier `~/cours-devops` est **indispensable au chapitre 3** (`cd ~/cours-devops`). Vérifier sur le maximum d'écrans avant de passer au Markdown.

**🎤 / 🛠️ Markdown**

- Montrer l'éditeur et l'aperçu côte à côte (`Ctrl + K` puis `V` ouvre l'aperçu à côté) : l'effet « je tape, ça se met en forme » marque les esprits.
- Rappeler que la fiche servira au chapitre 4 (profil GitHub) : elle doit être dans `cours-devops` et s'appeler exactement `presentation.md`.
- Pour les rapides : 🟡 lien et tableau, 🔴 case à cocher et image ; ils peuvent aussi explorer `Markdown All in One` (raccourci `Ctrl + B` pour mettre en gras).

**Gestion du temps (si retard, dans cet ordre)**

1. Supprimer l'enquête PYPL (le professeur montre le site en 1 min).
2. Réduire le quiz « Les EDI » à Q1 seulement.
3. Faire le quiz terminal à l'oral en 2 min.
4. Laisser la partie 🟡/🔴 de la fiche Markdown à la maison.
5. Ne **jamais** sacrifier la création de `~/cours-devops` ni `presentation.md` : ils sont réutilisés aux chapitres 3 et 4.

### Script de démonstration

**👀 Démo 1 · Visite guidée de l'interface (≈ 8 min)**

1. Ouvrir VS Code sur une fenêtre vide. Montrer les 5 zones dans l'ordre ① à ⑤ en les survolant à la souris.
2. Barre d'activités : cliquer successivement sur Explorateur, Recherche, Contrôle de code source (« on y reviendra au chapitre 3 »), Extensions.
3. Palette de commandes : `Ctrl + Maj + P`, taper « thème », montrer la prévisualisation en direct avec les flèches, puis `Échap` pour annuler. Taper « terminal » pour montrer qu'on peut ouvrir le terminal de là.
4. Extensions : `Ctrl + Maj + X`, chercher **Markdown All in One**, montrer l'éditeur (*Yzhang*), le nombre de téléchargements, cliquer **Installer**. Faire remarquer : « vérifiez toujours l'éditeur et le nombre de téléchargements, il existe des copies ».
5. Montrer l'onglet **Installé** de la vue Extensions : c'est là que les étudiants vérifieront leur travail.

Ce qui peut mal tourner : la place de marché ne charge pas (proxy, Wi-Fi). Rebondir avec les captures `images/edi5.png` et `images/edi6.png` du support et passer à la suite.

**👀 Démo 2 · Se promener dans ses dossiers (≈ 5 min)**

1. Ouvrir le terminal : `` Ctrl + ` ``. Montrer l'invite.
2. Taper, en commentant à voix haute :

   ```bash
   pwd             # "je suis dans mon dossier personnel"
   ls              # "je vois Documents, Bureau, Téléchargements..."
   cd Doc          # puis Tab : "le terminal complète tout seul"
   pwd             # "le chemin a changé"
   cd ..
   pwd             # "je suis remonté d'un étage"
   cd ~            # "retour à la maison"
   ```

3. Appuyer sur **↑** plusieurs fois pour montrer l'historique.
4. Faire remarquer que `pwd` et `ls` ne changent rien, qu'ils servent à se repérer.

Ce qui peut mal tourner : sur un Mac ou un Windows récent, `Documents` peut être synchronisé dans OneDrive ou iCloud et avoir un nom différent (`OneDrive/Documents`). Utiliser alors un autre dossier visible dans `ls`. Si le nom d'utilisateur contient un espace, ne pas s'y attarder, `cd ~` reste fiable.

### Réponses du quiz

**🧠 Quiz · Les EDI**

| Question | Réponse | Explication | Piège typique |
|---|---|---|---|
| Q1. Que signifie EDI ? | **B** | Environnement de Développement Intégré. | **D** est aussi un sens réel du sigle EDI (Échange de Données Informatisé), utilisé dans le commerce pour l'échange de factures entre entreprises. Ici on parle bien d'Environnement de Développement Intégré. |
| Q2. À quoi sert un débogueur ? | **B** | Exécuter le code pas à pas pour trouver et corriger les erreurs. | Confondre avec la coloration syntaxique (A). |
| Q3. Couleurs différentes selon les mots ? | **La coloration syntaxique** | Chaque mot est coloré selon son rôle dans le langage. | Répondre « le thème » : le thème choisit les couleurs, la coloration syntaxique les applique selon le rôle des mots. |

**🧠 Quiz · Le terminal**

| Question | Réponse | Explication | Piège typique |
|---|---|---|---|
| Q1. Afficher le dossier courant ? | **C** · `pwd` | *print working directory*. | Confondre avec `ls` (liste le contenu, pas l'emplacement). |
| Q2. Revenir au dossier parent ? | `cd ..` | `..` désigne le dossier parent. | Oublier l'espace (`cd..` marche sous PowerShell mais pas sous Bash). |
| Q3. Que fait `code .` ? | Ouvre le dossier courant dans VS Code | `.` veut dire « ici ». | Croire que cela crée un fichier. |
| Q4. Touche d'autocomplétion ? | **Tab** | Complète les noms de fichiers et dossiers. | Répondre « Entrée ». |

**🧠 Quiz · Bilan du chapitre**

| Question | Réponse | Explication | Piège typique |
|---|---|---|---|
| Q1. Visual Studio = Visual Studio Code ? | **Faux** | Visual Studio est un gros EDI pour Windows et .NET ; Visual Studio Code est un éditeur léger et multi-plateforme. | Le nom presque identique. |
| Q2. Raccourci de la palette de commandes ? | `Ctrl + Maj + P` (`Cmd + Maj + P` sur Mac) | Donne accès à toutes les actions. | Confondre avec `Ctrl + P` (ouverture rapide de fichier). |
| Q3. Page web mise à jour à chaque sauvegarde ? | **Live Server** | Elle servira au chapitre 3. | Répondre Prettier (mise en forme du code). |
| Q4. Mot en gras en Markdown ? | `**mot**` | Deux astérisques de chaque côté. | Un seul astérisque donne de l'italique. |

Suggestion : faire les quiz à main levée, avec des cartons A/B/C/D, ou sur Wooclap/Kahoot ; répondre par équipe pour le décompte des points.

### Corrigés des exercices

**🛠️ L'enquête PYPL**

- Résultat attendu : le top 3 affiché sur [pypl.github.io/IDE.html](https://pypl.github.io/IDE.html) le jour de la séance (vérifier soi-même avant le cours). En décembre 2024 : Visual Studio et VS Code (≈ 43 %, en cumulé selon la présentation du site), Eclipse (≈ 10 %), Android Studio (≈ 9 %).
- 🟡 Le site affiche une colonne de tendance sur un an (*Trend*) : la plus forte valeur positive désigne l'EDI qui a le plus progressé. Pistes d'explication attendues : essor de la data et de Python (PyCharm, Jupyter), succès de VS Code et de ses extensions, assistants IA intégrés.
- Erreur fréquente : lire le classement des **langages** (page d'accueil PYPL) au lieu de celui des **EDI**.

**🛠️ Personnalisez votre atelier**

1. Extensions : vue Extensions (`Ctrl + Maj + X`), rechercher chaque nom, **Installer**. Vérifier dans l'onglet **Installé**. Le French Language Pack demande de redémarrer (bouton **Changer de langue et redémarrer**).
2. Thème : `Ctrl + Maj + P` > « thème » > **Préférences : Thème de couleur**, choisir avec les flèches, `Entrée`.
3. Auto Save : menu **Fichier > Enregistrement automatique** ; une coche apparaît devant l'option.
4. 🟡 Police : `Ctrl + ,` (`Cmd + ,` sur Mac), rechercher « font size », modifier **Editor: Font Size** (par exemple 16). Alternative rapide : zoom de toute l'interface avec `Ctrl + =` / `Ctrl + -`.
5. 🔴 Capture d'écran : `Win + Maj + S` (Windows), `Cmd + Maj + 4` (Mac).

Critères pour valider : interface en français, thème modifié, coche devant **Enregistrement automatique**, extensions dans **Installé**.
Erreurs fréquentes : installer une extension au nom proche (vérifier l'éditeur) ; ne pas redémarrer après le French Language Pack ; chercher Auto Save dans les paramètres au lieu du menu Fichier.

**🛠️ Votre premier dossier de travail**

```bash
cd ~
pwd                  # /home/prenom, /Users/prenom ou C:\Users\prenom
mkdir cours-devops
cd cours-devops
pwd                  # .../cours-devops
code .
```

- 🟡 Solution :

  ```bash
  mkdir essais
  cd essais
  pwd                  # .../cours-devops/essais
  cd ..
  pwd                  # .../cours-devops
  ```

- 🔴 Solution : `cd ~/cours-devops` (fonctionne depuis n'importe où, y compris sous PowerShell). C'est exactement la commande utilisée au début du chapitre 3.
- Critère pour valider : une fenêtre VS Code avec `COURS-DEVOPS` en haut de l'Explorateur.
- Erreurs fréquentes : `code` introuvable (voir le tableau de dépannage) ; dossier créé ailleurs parce que l'étudiant a oublié `cd ~` (le retrouver avec `pwd` et le déplacer ou le recréer) ; faute de frappe (`cours_devops`, `Cours-Devops`) : faire corriger tout de suite, le chapitre 3 utilise exactement `cours-devops`.

- Critères pour valider : fichier nommé `presentation.md` dans `cours-devops`, l'aperçu (`Ctrl + Maj + V`) affiche un titre, du gras, des sous-titres et des listes.
- Erreurs fréquentes :
  - fichier nommé `presentation.md.txt` ou `Presentation.md` : renommer (clic droit > Renommer) ;
  - pas d'espace après `#` ou `-` (`#Titre`) : le titre ne s'affiche pas ;
  - tableau sans ligne `|---|---|` ou sans ligne vide avant : il s'affiche comme du texte brut ;
  - les crochets `[Votre prénom]` laissés tels quels : les remplacer entièrement ;
  - l'image ne s'affiche pas : le lien doit pointer directement vers un fichier image (`.png`, `.jpg`), pas vers une page web.

## Pièges fréquents et dépannage

| Symptôme | Cause | Solution |
|---|---|---|
| L'étudiant a installé **Visual Studio** (icône violette) | Confusion de nom | Désinstaller si besoin et installer **Visual Studio Code** depuis code.visualstudio.com. |
| `code` : commande introuvable (Windows) | Le PATH n'est pris en compte qu'au redémarrage de VS Code, ou « Ajouter à PATH » décoché | Fermer et rouvrir VS Code ; sinon réinstaller en cochant **Ajouter à PATH**. En dernier recours, **Fichier > Ouvrir le dossier**. |
| `code` : command not found (Mac) | La commande shell n'est pas installée | Palette de commandes > **Shell Command: Install 'code' command in PATH**. |
| VS Code disparaît sur Mac après redémarrage | L'application est restée dans Téléchargements | La glisser dans **Applications**. |
| `mkdir` : le fichier existe déjà | Le dossier a déjà été créé | Continuer avec `cd cours-devops`. |
| L'étudiant ne sait plus où il est | Trop de `cd` | `cd ~` puis `pwd`, et recommencer. |
| Le raccourci `` Ctrl + ` `` ne fait rien | Clavier où la touche ` est une touche morte (AZERTY : `Alt Gr + 7`) | Menu **Terminal > Nouveau terminal**, ou palette de commandes > « terminal ». |
| L'interface reste en anglais | Pas de redémarrage après le French Language Pack | Palette > **Configure Display Language** > `fr`, puis redémarrer. |
| La barre d'activités a disparu | Masquée par erreur | **Affichage > Apparence > Barre d'activités**. |
| L'aperçu Markdown ne s'ouvre pas | Le fichier n'a pas l'extension `.md` | Renommer en `presentation.md`. |
| Installation impossible (pas de droits admin) | Ordinateur d'entreprise verrouillé | Installeur **User** sur Windows ; sinon binôme pour la séance et [vscode.dev](https://vscode.dev) en dépannage. |
| La place de marché ne charge pas | Wi-Fi saturé ou proxy | Réessayer plus tard ; installer les extensions à la maison. |
