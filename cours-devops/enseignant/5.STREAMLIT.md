## En bref

- **Durée :** 4h, en **2 séances de 2h**.
  - Séance 1 : Python et Streamlit, installation du projet (dépôt, `stenv`, `.gitignore`, `requirements.txt`), première appli, widgets.
  - Séance 2 : données (`ventes.csv`, pandas), indicateurs, graphiques, filtre, dépôt de fichier, déploiement (bonus), mission d'équipe.
- **Matériel :** un ordinateur par étudiant avec VS Code (extensions **Python** et **Rainbow CSV**), Git, un compte GitHub. Vidéoprojecteur. Connexion Internet correcte (le `pip install` de Streamlit télécharge environ 50 à 100 Mo par poste : prévoir que le Wi-Fi sature si 30 postes installent en même temps, et lancer l'installation tôt).
- **À vérifier avant la séance 1 :**
  - avoir envoyé aux étudiants, quelques jours avant, la section « 💻 À préparer avant la séance : installer Python » du support ;
  - sur le poste de démonstration : Python 3.10+ installé, un dépôt `datacafe-streamlit` **vide** prêt à être créé en direct (ou un compte GitHub de démonstration), la police du terminal et de l'éditeur agrandie (Ctrl + + dans VS Code), le navigateur à côté de VS Code (écran partagé) ;
  - si possible, un poste Windows **et** un Mac à portée pour montrer les deux activations ;
  - un `ventes.csv` prêt sur une clé ou dans le chat de la classe, pour les étudiants qui tapent lentement (séance 2).
- **À vérifier avant la séance 2 :** les équipes de 4 du projet sont connues ; chaque étudiant a son dépôt `datacafe-streamlit` avec `app.py` fusionné sur `main`.
- **Fil DataCafé :** Sofia en a assez de refaire les graphiques Excel chaque lundi ; l'équipe construit une application web Streamlit des ventes, une fonctionnalité par branche et par Pull Request.
- **Les 3 messages clés :**
  1. **Streamlit relit tout le script à chaque interaction** : c'est ce qui rend l'appli si simple à écrire (et explique le comportement du bouton).
  2. **Un projet Python = une valise (`stenv`) + une liste des courses (`requirements.txt`) + un videur (`.gitignore`) écrit avant le premier `git add`.** « Pas de `(stenv)`, pas de Streamlit ! »
  3. **Chaque fonctionnalité = une branche + une Pull Request** : on réutilise le GitHub Flow du chapitre 4 sur un vrai produit.

**Continuité avec le chapitre 6 :** le chapitre 6 réutilise le dépôt `datacafe-streamlit`, l'environnement `stenv`, le `.gitignore`, `requirements.txt`, `ventes.csv` (colonnes `date,produit,region,quantite,prix_unitaire`) et `ventes_app.py`. S'assurer en fin de séance 2 que tout est fusionné sur `main`.

### Points d'animation

**💬 Tour de table.** Garder au tableau les « 3 chiffres du directeur » (souvent : chiffre d'affaires, nombre de ventes, produit star) : on y revient en fin de séance 2. Faire parier sur le nombre de lignes : la réponse (3 lignes) fait toujours son effet.

**🎤 Python et Streamlit.** Rester très concret, pas de théorie sur les langages. Lire le `if tasses > 5` à voix haute « en français » pour montrer que Python se lit. Écrire au tableau en gros : **« À chaque clic, Streamlit relit tout le script »** et le laisser affiché toute la séance. Demander : « Combien d'entre vous ont déjà écrit du code ? » pour calibrer.

**🎤 Fondations.** Faire mimer la valise : « Karim a besoin de Streamlit 1.30, vous de la 1.40 : on met tout dans la même valise ? » Pour le videur : « Celui qui est déjà dans la boîte, le videur le met dehors ? Non. Donc le `.gitignore`, avant le premier `git add`. »

**🛠️ Préparer le projet.** C'est l'étape la plus risquée du chapitre.

- Avancer **étape par étape** en projetant son propre écran ; à chaque étape, demander un signal (pouce levé, ou post-it vert/rouge sur l'écran) et ne passer à la suite que quand 80 % de la classe a le pouce levé.
- Installer les débutants **en binôme** avec un étudiant à l'aise : l'un tape, l'autre vérifie, puis on inverse sur le deuxième poste.
- Lancer le `pip install` **le plus tôt possible** (pendant qu'il tourne, expliquer `requirements.txt`).
- Montrer explicitement `git status` **avant** et **après** le `.gitignore` : la disparition de `stenv/` est le moment « aha ».
- Les rapides : défi 🔴 (nouveau terminal), puis aider un voisin, puis lire le 🔬 sur l'épinglage des versions.

**🎤 GitHub Flow.** Rappel éclair : demander à un étudiant de dicter les 8 étapes pendant qu'on les écrit au tableau. Laisser ce schéma au tableau jusqu'à la fin de la séance.

**👀 Hello DataCafé.** Les étudiants **ne tapent pas** pendant la démo : ils regardent. Annoncer « vous referez exactement la même chose juste après ».

**🛠️ Votre première appli.** Problèmes les plus fréquents : environnement non activé dans le deuxième terminal, fichier `app.py` créé hors du dépôt, `push` sur `main` au lieu de la branche. Rapides : 🟡 liste Markdown, puis inviter le voisin comme collaborateur et faire approuver la PR.

**🎤 Widgets.** Faire deviner : « Sur une borne de fast-food, quels widgets voyez-vous ? » (boutons, quantité, choix de boisson, options). Faire remarquer que **tous** suivent la même forme `variable = st.widget("texte", ...)`.

**🛠️ Bouton et curseur.** Exiger que les étudiants écrivent les commandes Git **sans regarder** le support (seulement le schéma au tableau). Les rapides passent à la carte et aux suppléments, puis aux défis 🔴.

### Script de démonstration

#### 👀 Préparer le projet (fait en direct pendant le 🛠️)

1. Sur GitHub, créer `datacafe-streamlit` (Public, **Add a README file**, .gitignore **None**). Montrer où cliquer, lentement.
2. `cd ~/cours-devops`, `git clone https://github.com/<pseudo>/datacafe-streamlit.git`, `cd datacafe-streamlit`, `code .`. **Insister** : `code .` ouvre une nouvelle fenêtre, il faut y rouvrir un terminal. Faire taper `pwd` à tout le monde.
3. `python -m venv stenv` (Mac/Linux : `python3`). Montrer le dossier `stenv` dans la barre latérale ; cliquer **Yes** sur la proposition de VS Code.
4. `git status` → `stenv/` apparaît. Demander : « On l'envoie sur GitHub ? » Créer `.gitignore`, copier le contenu, sauvegarder, `git status` → `stenv/` a disparu.
5. Activer : `stenv\Scripts\activate` (PowerShell). Montrer le `(stenv)`. Si l'on a un Mac à côté : `source stenv/bin/activate`.
6. `requirements.txt` avec `streamlit`, puis `python -m pip install -r requirements.txt`. Pendant l'installation (1 à 3 min), expliquer la liste des courses et le 🔬 épinglage.
7. `streamlit version`, puis commit des fondations : `git add .gitignore requirements.txt`, `git commit`, `git push`. Rafraîchir GitHub : pas de `stenv`.
8. `streamlit hello` → Entrée à la question de l'e-mail → montrer deux démos → `Ctrl + C` dans le terminal.

**Ce qui peut mal tourner en direct :** la politique d'exécution PowerShell sur le poste de démo (la corriger devant tout le monde : c'est utile, la moitié de la classe sur Windows va la rencontrer) ; le Wi-Fi lent (avoir déjà un `stenv` installé dans un autre dossier pour continuer la démo pendant que la classe installe).

#### 👀 Hello DataCafé : script de live coding (10 min)

Préparation : appli **non lancée**, terminal propre, `(stenv)` visible, VS Code à gauche, navigateur à droite.

1. **(0:00)** « On applique la recette : on part de `main` à jour et on crée une branche. »
   ```bash
   git switch main
   git pull
   git switch -c premiere-appli
   ```
2. **(0:01)** Créer `app.py`. Taper **lentement** en commentant à voix haute :
   ```python
   import streamlit as st
   ```
   « On emprunte le livre de recettes Streamlit, et on l'appelle `st`. »
   ```python
   st.title("☕ DataCafé")
   st.write("Bonjour ! Bienvenue dans la première application de l'équipe DataCafé.")
   ```
   `Ctrl + S`. « Trois lignes. Qui avait parié 3 ? »
3. **(0:03)** `streamlit run app.py`. Montrer la ligne *Local URL: http://localhost:8501* dans le terminal, puis l'appli dans le navigateur. Expliquer `localhost` et le port.
4. **(0:04)** Ajouter le café du jour :
   ```python
   st.header("Le café du jour")
   st.write("Aujourd'hui, le barista vous recommande un **cappuccino** à la cannelle. 🤎")
   ```
   Sauvegarder → faire remarquer **File change** → cliquer **Always rerun**. Faire remarquer le gras (Markdown).
5. **(0:05)** **Erreur volontaire** : retirer un guillemet fermant, sauvegarder. Montrer le message rouge dans le navigateur avec le numéro de ligne. Corriger. « Une erreur n'est pas grave : Streamlit vous dit où elle est. »
6. **(0:06)** Ajouter un `st.caption("Source : ventes DataCafé")` pour montrer le tableau des fonctions de texte, puis le retirer ou le garder.
7. **(0:07)** Essayer de taper `git status` dans le terminal de Streamlit : rien ne se passe. « Le terminal est occupé. » Ouvrir un deuxième terminal avec **+** ; faire remarquer qu'il n'y a **pas** de `(stenv)` (pas grave pour Git, indispensable pour Python).
8. **(0:08)** Dans le deuxième terminal :
   ```bash
   git status
   git add app.py
   git commit -m "Première application Streamlit : titre et café du jour"
   git push -u origin premiere-appli
   ```
9. **(0:09)** Sur GitHub : **Compare & pull request**, titre et description, **Create**, onglet **Files changed** (« on se relit comme un collègue »), **Merge**, **Confirm**, **Delete branch**.
10. **(0:10)** Retour au terminal : `git switch main`, `git pull`, `git branch -d premiere-appli`.

**Ce qui peut mal tourner :** le navigateur ne s'ouvre pas (copier l'URL du terminal) ; port 8501 occupé par un `streamlit hello` resté ouvert (l'appli s'ouvre en 8502 : en profiter pour montrer qu'il faut arrêter l'ancienne avec `Ctrl + C`) ; `streamlit` introuvable (l'environnement n'est pas actif : montrer `python -m streamlit run app.py` comme plan B).

#### 👀 Le bouton et la magie des branches (5 min)

1. `git switch main`, `git pull`, `git switch -c ajout-bouton`.
2. Coller le bloc du bouton, sauvegarder, cliquer : ballons. Rafraîchir la page : le message d'attente revient. Expliquer avec la phrase au tableau.
3. `git add app.py`, `git commit -m "Ajout du bouton de commande"`, `git switch main` **pendant que l'appli tourne** : le bouton disparaît (avec Always rerun ; sinon cliquer **Rerun**). `git switch ajout-bouton` : il revient.
4. Ne pas faire la PR en direct (gain de temps) : « vous la ferez vous-mêmes dans l'exercice ».

**Piège en direct :** si l'on a oublié de commiter avant `git switch main`, Git emporte la modification non commitée sur `main` et le bouton ne disparaît pas. Bon prétexte pour rappeler : on commite avant de changer de branche.

### Corrigés des exercices

#### 🛠️ Préparer le projet `datacafe-streamlit`

Résultat attendu : le dépôt GitHub contient `README.md`, `.gitignore`, `requirements.txt` (une ligne `streamlit`) et **pas** `stenv`. `git log --oneline` montre 2 commits (Initial commit, Ajout du .gitignore et des dépendances). Le terminal affiche `(stenv)`.

**Défi 🔴 (nouveau terminal) :** dans un nouveau terminal, l'environnement n'est **plus activé** (pas de `(stenv)`) : la commande `streamlit` est introuvable, car Streamlit est installé **dans la valise**, pas sur l'ordinateur. Il suffit de réactiver l'environnement (`stenv\Scripts\activate`, ou `source stenv/bin/activate`).

**Valider :** le voisin vérifie les 5 points ; le professeur regarde la page GitHub (dossier `stenv` absent).

**Erreurs fréquentes :** `.gitignore` enregistré sous `.gitignore.txt` (Windows, extensions masquées) ou `gitignore` sans le point ; `venv/` au lieu de `stenv/` ; `stenv` créé dans `~/cours-devops` au lieu du dépôt (faire `pwd`) ; `requirements.txt` vide car non sauvegardé.

```python
import streamlit as st

st.title("☕ DataCafé")
st.write("Bonjour ! Bienvenue dans la première application de l'équipe DataCafé.")

st.header("Le café du jour")
st.write("Aujourd'hui, le barista vous recommande un **cappuccino** à la cannelle. 🤎")

st.header("🔔 La sonnette du comptoir")

if st.button("Commander un café"):
    st.write("☕ Et un café, un ! Bonne dégustation.")
    st.balloons()
else:
    st.write("😴 Le barista attend votre commande...")

st.header("📏 Votre consommation de café")

tasses = st.slider("Combien de tasses de café buvez-vous par jour ?", 0, 10, 2)
st.write("Vous buvez", tasses, "tasse(s) par jour, soit", tasses * 7, "par semaine !")

if tasses >= 5:
    st.warning("Attention, ça fait beaucoup de caféine ! 😵‍💫")

budget = st.slider("Votre budget café par mois (en €)", 0, 100, (20, 50))
st.write("Votre budget est compris entre", budget[0], "et", budget[1], "€.")

st.header("📋 La carte")

cafe = st.selectbox(
    "Quel café voulez-vous ?",
    ["Espresso", "Cappuccino", "Latte", "Mocha", "Cold brew"],
)
st.write("Excellent choix : un", cafe, "! 😋")

prix = {"Espresso": 2.0, "Cappuccino": 3.5, "Latte": 3.8, "Mocha": 4.2, "Cold brew": 4.0}

total = prix[cafe] * tasses
st.metric("Votre budget café de la semaine", f"{total * 7:.2f} €")

st.header("🍯 Les suppléments")

supplements = st.multiselect(
    "Quels suppléments voulez-vous ?",
    ["Sucre", "Lait d'avoine", "Caramel", "Chantilly", "Cannelle"],
    default=["Sucre"],
)
st.write("Vous avez choisi :", supplements)
st.write("Nombre de suppléments :", len(supplements))

if len(supplements) > 3:
    st.error("Ce n'est plus un café, c'est un dessert ! 🍰")
```

**Erreurs fréquentes :** `NameError: name 'tasses' is not defined` pour le ticket de caisse si le code est collé **au-dessus** du curseur (rappel : le script est lu de haut en bas) ; `KeyError: 'Mocha '` si une liste et le dictionnaire ne sont pas orthographiés pareil ; `default=["sucre"]` (minuscule) provoque une erreur car la valeur par défaut doit figurer dans la liste des choix.

#### 👥 Le dashboard DataCafé à 4 mains

Une solution possible pour `app.py` sur `main` en fin de mission :

```python
import pandas as pd
import streamlit as st

st.set_page_config(page_title="Dashboard DataCafé", page_icon="☕", layout="wide")
st.title("☕ Tableau de bord DataCafé")

ventes = pd.read_csv("ventes.csv")
ventes["chiffre_affaires"] = ventes["quantite"] * ventes["prix_unitaire"]

# ===== FILTRE (chef d'équipe) =====
st.sidebar.header("🔎 Filtres")
regions = st.sidebar.multiselect(
    "Régions",
    ["Paris", "Lyon", "Marseille"],
    default=["Paris", "Lyon", "Marseille"],
)
ventes = ventes[ventes["region"].isin(regions)]

# ===== KPI 1 : chiffre d'affaires et cafés vendus (Léa) =====
col1, col2 = st.columns(2)
col1.metric("💶 Chiffre d'affaires", f"{ventes['chiffre_affaires'].sum():.2f} €")
col2.metric("☕ Cafés vendus", int(ventes["quantite"].sum()))

# ===== KPI 2 : chiffre d'affaires par produit (Karim) =====
st.subheader("Chiffre d'affaires par produit")
st.bar_chart(ventes.groupby("produit")["chiffre_affaires"].sum())

# ===== KPI 3 : évolution jour après jour (Sofia) =====
st.subheader("Évolution des ventes jour après jour")
st.line_chart(ventes.groupby("date")["quantite"].sum())

# ===== KPI 4 : ventes par région (Tom) =====
st.subheader("Ventes par région")
par_region = ventes.groupby("region")[["quantite", "chiffre_affaires"]].sum()
st.dataframe(par_region)
if len(par_region) > 0:
    st.caption(f"🏆 Région championne : {par_region['chiffre_affaires'].idxmax()}")
```

Indicateurs 🔴 possibles : produit star `ventes.groupby("produit")["chiffre_affaires"].sum().idxmax()` (Cappuccino) ; prix moyen d'une vente `ventes["chiffre_affaires"].mean()` (74.23 €) ; meilleure journée `ventes.groupby("date")["quantite"].sum().idxmax()` (2026-03-05).

## Pièges fréquents et dépannage

| Symptôme | Cause | Solution |
|---|---|---|
| PowerShell : « l'exécution de scripts est désactivée sur ce système » (*running scripts is disabled*) en activant `stenv` | Politique d'exécution Windows par défaut (`Restricted`) | `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser`, répondre **O**, relancer `stenv\Scripts\activate`. Si le poste est verrouillé par l'école : passer au terminal **Git Bash** (`source stenv/Scripts/activate`) ou, pour la session seulement, `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` |
| `stenv\Scripts\activate` non reconnu | Variante de PowerShell | `.\stenv\Scripts\Activate.ps1` |
| `streamlit: command not found`, `'streamlit' n'est pas reconnu`, `ModuleNotFoundError: No module named 'streamlit'` | Environnement **pas activé** dans ce terminal (nouveau terminal, VS Code relancé, deuxième terminal) | Réactiver (`(stenv)` doit apparaître). Plan B : `python -m streamlit run app.py`. Dans VS Code : `Ctrl + Maj + P` → **Python: Select Interpreter** → `stenv` (les nouveaux terminaux s'activent alors souvent tout seuls) |
| `pip install` installe « ailleurs », Streamlit introuvable malgré une installation réussie | `pip` tout court appelle le pip d'un autre Python (Store, Anaconda, Python système) | Toujours `python -m pip install ...`, **environnement activé**. Vérifier avec `python -m pip --version` que le chemin contient `stenv` |
| `pip` introuvable, mais `python -m pip` fonctionne | `Scripts` de Python pas dans le PATH | Utiliser `python -m pip` (c'est la forme du cours) |
| L'appli s'ouvre sur `localhost:8502`, `8503`... ou deux versions de l'appli coexistent | Le port 8501 est **déjà utilisé** par une autre appli Streamlit (autre terminal, `streamlit hello` resté ouvert) | `Ctrl + C` dans les terminaux concernés, ou fermer les terminaux à la poubelle de VS Code. Forcer un port : `streamlit run app.py --server.port 8510` |
| `Port 8501 is already in use` (le serveur ne démarre pas) | Port occupé, ou processus Streamlit zombie | Fermer tous les terminaux VS Code ; sous Windows `netstat -ano \| findstr 8501` puis `taskkill /PID <pid> /F` ; sous macOS/Linux `lsof -i :8501` puis `kill <pid>` ; ou changer de port |
| Taper `python` ouvre le Microsoft Store | Python pas installé ou alias d'exécution actifs | Installer Python en cochant **Add python.exe to PATH**, ou désactiver les alias (**Gérer les alias d'exécution d'application**). Essayer `py` |
| `python` inconnu sur Mac | La commande s'appelle `python3` | `python3 -m venv stenv` ; après activation, `python` fonctionne |
| `ensurepip is not available` (Linux) | Paquet `python3-venv` absent | `sudo apt install python3-venv`, supprimer `stenv`, recommencer |
| `stenv/` apparaît encore dans `git status` | `.gitignore` mal nommé (`.gitignore.txt`, `gitignore`), pas sauvegardé, ou contenant `venv/` au lieu de `stenv/` | Vérifier le nom (`ls -a`), sauvegarder, corriger le contenu |
| `stenv` déjà sur GitHub | Commité avant le `.gitignore` | `git rm -r --cached stenv`, `git add .gitignore`, commit, push |
| `Error: Invalid value: File does not exist: app.py` | Mauvais dossier, ou fichier mal nommé | `pwd`, `ls` ; renommer `App.py` / `app.py.txt` |
| La page ne se met pas à jour | **Always rerun** non activé, ou fichier non sauvegardé | `Ctrl + S`, cliquer **Rerun** / **Always rerun** |
| `IndentationError`, `SyntaxError` | Décalage, guillemet ou parenthèse | Lire le numéro de ligne dans l'erreur |
| `FileNotFoundError: 'ventes.csv'` | `streamlit run` lancé hors de la racine du dépôt | `cd` à la racine puis relancer |
| `KeyError: 'quantite'` | En-tête du CSV mal recopié | Corriger la première ligne du CSV |
| `git push` refusé (403) sur `dashboard-datacafe` | Invitation de collaborateur non acceptée | Accepter l'invitation (e-mail ou `github.com/notifications`) |
| Le terminal ne répond plus aux commandes Git | Il est occupé par `streamlit run` | Deuxième terminal (bouton **+**) ou `Ctrl + C` |
| Wi-Fi saturé pendant `pip install` | 30 postes téléchargent en même temps | Échelonner par rangées, ou faire installer Streamlit en même temps que Python avant la séance |
