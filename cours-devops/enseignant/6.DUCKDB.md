  3. **On versionne les ingrédients et la recette, pas le plat cuisiné** : le CSV, les `.sql` et le `.py` vont dans Git ; la base `*.duckdb` non.

### Script de démonstration

**👀 Premiers pas (10 min).** Partir d'un clone de démonstration à jour, sur `main`.

1. `cd ~/cours-devops/datacafe-streamlit`, `git switch main`, `git pull`, `git switch -c analyse-sql`. Faire remarquer le nom de branche dans la barre d'état de VS Code.
2. Ouvrir `ventes.csv`, tout sélectionner (`Ctrl + A`), coller les 18 lignes du support. Montrer les couleurs de Rainbow CSV. `git add ventes.csv` puis `git commit -m "Historique des ventes du 1er trimestre 2026"`.
3. `duckdb datacafe.duckdb` : faire remarquer l'invite `D` et le nouveau fichier `datacafe.duckdb` dans l'explorateur.
4. Taper `SELECT * FROM 'ventes.csv'` **sans** le `;` et appuyer sur Entrée : montrer le `‣`, puis taper `;`. Faire remarquer la ligne des types (`date`, `varchar`, `int64`, `double`).
5. `CREATE TABLE ventes AS SELECT * FROM read_csv('ventes.csv');` puis `SELECT * FROM ventes;`, `DESCRIBE ventes;`, `SUMMARIZE ventes;` (ne pas répondre aux questions de l'exercice : laisser les étudiants lire le résultat).
6. `.quit`, `git status` : montrer `datacafe.duckdb` non suivi. Compléter le `.gitignore` (`*.duckdb`, `*.duckdb.wal`), `git status` à nouveau (il a disparu), `git add .gitignore`, `git commit -m "Ignore les bases DuckDB"`.

Ce qui peut mal tourner :
- **`No files found that match the pattern "ventes.csv"`** : DuckDB n'a pas été lancé depuis le dossier du dépôt. En profiter pour montrer `pwd`.
- **`Table with name ventes already exists`** si on rejoue la démo : utiliser `CREATE OR REPLACE TABLE ventes AS ...` ou supprimer `datacafe.duckdb` avant la séance.
- **Le `‣` qui ne part pas** (apostrophe ouverte non fermée) : taper `';` ou `Ctrl + C` pour annuler la saisie.

**👀 Niveau 1.** Taper la requête `montant` en commentant chaque mot. Montrer ensuite `SELECT * FROM ventes;` : la table n'a pas changé.

**👀 Niveau 2.** Taper `WHERE region = 'Paris'` (5 lignes). Puis provoquer :
- `WHERE region = "Paris"` → erreur *Referenced column "Paris" not found* ;
- `WHERE region = 'paris'` → **0 ligne, sans erreur**. Insister.
Montrer aussi `WHERE date >= '2026-03-01'` (6 lignes, les ventes de mars).

**👀 Niveau 3.** Le podium (75 / 70 / 60). Puis enlever `LIMIT 3` pour montrer le classement complet, et enlever `DESC` pour montrer l'ordre croissant.

**👀 Niveau 4.** Les chiffres clés (18 / 58 / 678.5 / 3.22), puis la requête Espresso : **21** paquets. Demander à la classe de deviner le résultat avant d'appuyer sur Entrée.

**👀 Niveau 5.** CA par région (Paris 202.0, Lyon 177.5, Marseille 161.0, Lille 138.0). Puis provoquer l'erreur de la règle d'or : `SELECT region, produit, SUM(quantite) FROM ventes GROUP BY region;`. Enfin montrer le `HAVING` (résultat : Cappuccino 212.5 et Espresso 210.0).

### Corrigés des exercices

**🛠️ Premier contact**

- a) Du **2026-01-05** au **2026-03-30** (colonnes `min` et `max` de la ligne `date`).
- b) **7** paquets (colonne `max` de la ligne `quantite` : l'Espresso à Lyon le 6 février).
- c) **4** produits : Espresso, Cappuccino, Latte et Moka. (`approx_unique` est une estimation, très précise sur de petits fichiers.)
- 🟡 `LIMIT 3` n'affiche que les **3 premières lignes**. Très pratique pour jeter un œil à une table de 10 millions de lignes sans tout afficher.
- 🔴 Le code de la table `regions` est dans l'encadré du support ; `SELECT * FROM regions;` doit afficher 4 lignes (Karim 200, Tom 150, Sofia 180, Léa 150).
- Critères de validation : `.tables` affiche `ventes` (et `regions` pour les 🔴) ; `git status` ne montre pas `datacafe.duckdb` ; `git log --oneline` montre les deux commits.
- Erreurs fréquentes : `.gitignore` modifié mais pas commité ; `ventes.csv` complété au lieu d'être **remplacé** (doublons avec l'ancien fichier du chapitre 5 : vérifier que `SUMMARIZE` donne bien `count` = 18) ; DuckDB lancé depuis le mauvais dossier.

**🛠️ Le menu à la carte (niveau 1)**

```sql
SELECT region, produit
FROM ventes;

SELECT date, produit, prix_unitaire * 100 AS prix_centimes
FROM ventes;
```

18 lignes à chaque fois ; `prix_centimes` vaut 1000.0 (Espresso), 1250.0 (Cappuccino), 1500.0 (Moka), 1100.0 (Latte). Erreur fréquente : virgule oubliée entre deux colonnes (DuckDB prend alors le second nom comme alias du premier, sans erreur : `SELECT region produit` affiche une seule colonne nommée `produit` contenant les villes).

**🛠️ Le filtre à café (niveau 2)**

```sql
-- 1. 4 lignes (Lyon, Marseille, Paris, Lille)
SELECT * FROM ventes WHERE produit = 'Moka';

-- 2. 3 lignes (Espresso 7, Latte 5, Cappuccino 3)
SELECT * FROM ventes WHERE region = 'Lyon' AND quantite >= 3;

-- 3. 2 lignes (Latte du 10 février, Moka du 19 mars)
SELECT * FROM ventes WHERE produit IN ('Latte', 'Moka') AND region = 'Lille';

-- 4. 🟡 6 lignes
SELECT * FROM ventes WHERE date >= '2026-02-01' AND date < '2026-03-01';

-- 5. 🔴 2 lignes, avec les parenthèses obligatoires
SELECT * FROM ventes WHERE (produit = 'Latte' OR produit = 'Moka') AND region = 'Lille';
```

Pour la question 5 : **sans** les parenthèses, `produit = 'Latte' OR produit = 'Moka' AND region = 'Lille'` renvoie **5 lignes**, car `AND` est évalué avant `OR` : SQL comprend « un Latte n'importe où (4 lignes), ou bien un Moka à Lille (1 ligne) ». C'est pour ça que `IN` est plus sûr. Question 4 : accepter aussi `date BETWEEN '2026-02-01' AND '2026-02-28'` ou `strftime(date, '%m') = '02'`. Erreur fréquente : `date <= '2026-02-31'` (date inexistante, erreur de conversion).

**🛠️ Le podium (niveau 3)**

```sql
-- 1. 18 lignes, en tête : 2026-03-30 Cappuccino Marseille
SELECT * FROM ventes ORDER BY date DESC;

-- 2. En tête : Espresso à Lyon (7), Cappuccino à Marseille (6), puis Espresso à Lille (5), Latte à Lyon (5)...
SELECT * FROM ventes ORDER BY quantite DESC LIMIT 5;

-- 3. 🟡 Lille d'abord (Espresso 5, Latte 3, ...), puis Lyon, Marseille, Paris
SELECT * FROM ventes ORDER BY region, quantite DESC;
```

Question 2 : la 5e ligne est l'une des **trois ventes de 4 paquets** (Cappuccino, Moka ou Espresso, toutes à Paris). En cas d'égalité, l'ordre n'est pas garanti : rassurer les étudiants dont la dernière ligne diffère de celle du voisin.

**🛠️ La calculatrice géante (niveau 4)**

```sql
-- 1. 10.0 et 15.0
SELECT MIN(prix_unitaire) AS prix_min, MAX(prix_unitaire) AS prix_max
FROM ventes;

-- 2. 5 ventes
SELECT COUNT(*) FROM ventes WHERE region = 'Marseille';

-- 3. 🟡 248.5 €
SELECT SUM(quantite * prix_unitaire) AS ca_mars
FROM ventes
WHERE date >= '2026-03-01';
```

Erreur fréquente à la question 3 : `SUM(quantite)` (21 paquets) au lieu du montant.

**🛠️ Les questions du directeur (niveau 5)**

```sql
-- 1. Cappuccino 212.5 · Espresso 210.0 · Moka 135.0 · Latte 121.0
SELECT produit, SUM(quantite * prix_unitaire) AS chiffre_affaires
FROM ventes
GROUP BY produit
ORDER BY chiffre_affaires DESC;

-- 2. Espresso 21 · Cappuccino 17 · Latte 11 · Moka 9
SELECT produit, SUM(quantite) AS paquets
FROM ventes
GROUP BY produit
ORDER BY paquets DESC;
```

😮 **La surprise à mettre en scène :** l'**Espresso** est le café qui se vend **en plus grand nombre**, mais c'est le **Cappuccino** qui **rapporte le plus**, car il est plus cher. Tout dépend de la question posée : un bon analyste précise toujours **ce qu'il mesure**. (Remarquer aussi que le Moka passe devant le Latte en euros, mais derrière en paquets.)

```sql
-- 3. Lyon : 4 ventes, 4.0 en moyenne · Paris : 5 ventes, 3.4 · Lille : 4 ventes, 3.0 · Marseille : 5 ventes, 2.6
SELECT region, COUNT(*) AS nb_ventes, ROUND(AVG(quantite), 2) AS quantite_moyenne
FROM ventes
GROUP BY region;

-- 4. 🟡 16 lignes : une par couple (ville, produit)
SELECT region, produit, SUM(quantite) AS paquets
FROM ventes
GROUP BY region, produit
ORDER BY region, produit;

-- 5. 🔴 2026-01 : 192.0 · 2026-02 : 238.0 · 2026-03 : 248.5 → oui, ça progresse ! 📈
SELECT strftime(date, '%Y-%m') AS mois,
       SUM(quantite * prix_unitaire) AS chiffre_affaires
FROM ventes
GROUP BY mois
ORDER BY mois;
```

Détail de la question 4 (paquets) : Lille : Cappuccino 2, Espresso 5, Latte 3, Moka 2 · Lyon : Cappuccino 3, Espresso 7, Latte 5, Moka 1 · Marseille : Cappuccino 8, Espresso 2, Latte 1, Moka 2 · Paris : Cappuccino 4, Espresso 7, Latte 2, Moka 4.

Erreurs fréquentes : oublier le `GROUP BY` (erreur de la règle d'or) ; mettre `produit` dans le `SELECT` mais `region` dans le `GROUP BY` ; à la question 3, l'ordre des lignes varie si on n'ajoute pas d'`ORDER BY` (c'est normal).

## Pièges fréquents et dépannage

| Symptôme | Cause | Solution |
|---|---|---|
| `duckdb` : commande introuvable | Terminal non redémarré après l'installation, ou `PATH` non mis à jour (Mac/Linux) | Fermer **toutes** les fenêtres VS Code ; sur Mac/Linux, copier la ligne affichée par le script ; en attendant, `~/.duckdb/cli/latest/duckdb` ou [shell.duckdb.org](https://shell.duckdb.org) |
| `winget` introuvable / scripts désactivés (Windows) | Windows ancien ou poste verrouillé | Télécharger le `.zip`, copier `duckdb.exe` dans le dépôt, lancer `.\duckdb.exe`, ajouter `duckdb.exe` au `.gitignore` |
| Le terminal affiche `‣` et ne répond plus | `;` oublié, ou apostrophe non fermée | Taper `;` (ou `';`) puis Entrée ; `Ctrl + C` pour annuler |
| `No files found that match the pattern "ventes.csv"` | DuckDB, Python ou Streamlit lancé hors du dossier `datacafe-streamlit` | `.quit`, `pwd`, `cd ~/cours-devops/datacafe-streamlit`, relancer |
| `Referenced column "Paris" not found` | Guillemets doubles autour d'un texte | Apostrophes simples : `'Paris'` |
| Résultat vide, sans erreur | Majuscules (`'paris'`), espace en trop, ou mauvais nom de produit | Comparer avec `SELECT DISTINCT region FROM ventes;` |
| `must appear in the GROUP BY clause or must be part of an aggregate function` | Règle d'or non respectée | Ajouter la colonne au `GROUP BY` ou l'entourer d'un agrégat |
| `Table with name ventes already exists` | `CREATE TABLE` relancé | `CREATE OR REPLACE TABLE ...`, ou ne pas recréer la table |
| `Table with name ventes does not exist` | DuckDB lancé avec `duckdb` seul (base en mémoire) ou depuis un autre dossier | Relancer avec `duckdb datacafe.duckdb` dans le dépôt |
| `SUMMARIZE` donne plus de 18 lignes | Le nouveau CSV a été ajouté **à la suite** de l'ancien au lieu de le remplacer | Remplacer tout le contenu de `ventes.csv`, puis `CREATE OR REPLACE TABLE` |
| `datacafe.duckdb` apparaît dans `git status` | `.gitignore` non modifié ou faute de frappe | Ajouter `*.duckdb` ; si déjà commité : `git rm --cached datacafe.duckdb` puis commit |
| `Could not set lock on file "datacafe.duckdb"` | La base est ouverte à la fois dans le terminal DuckDB et dans Python | `.quit` dans DuckDB, ou `read_only=True` |
| `ModuleNotFoundError: No module named 'duckdb'` | `stenv` non activé, ou `pip install` non fait | Activer `stenv`, puis `pip install -r requirements.txt` |
| Graphique Streamlit vide | Ville mal orthographiée dans la liste du `selectbox` | Respecter exactement `Paris`, `Lyon`, `Marseille`, `Lille` |
| Le Titanic (🔬) ne se charge pas | Pas d'Internet ou proxy de l'école bloquant le téléchargement de `httpfs` | Encadré facultatif : passer |
